## 阶段边界

删除 Sigma 自建的旧内置工具实现、默认目录和未使用的旧工具扩展注册入口。Web 与协议入口不再注册 `ask/read/write/bash/edit/search/find/todo/activate_skill`，也不暴露 `Sigma.Coding.Tools` 的旧实现。本阶段结束时，未配置 MCP 的会话仍能聊天和使用现有 Backplane 子代理，但暂时没有文件、命令、图片、计划或提问等内置工具。

已比较两种做法：先退役旧工具，或同阶段接入 Codex 核心工具后切换。用户明确选择前者；后者需要 Provider custom 输入、结构化结果、持久化和跨轮命令资源的独立集成，留到下一阶段。

## 删除与保留

删除整个 `apps/sigma_tools/`、`apps/sigma_coding/lib/sigma_coding/tools/`、对应工具专项测试，以及仅服务旧工具 SDK 的 `ExtensionRegistry`。移除 Web 的 umbrella 依赖、默认目录接线和子代理对旧提问工具的包装。只使用旧工具充当夹具的通用运行时测试改用测试内工具，保留它们原有的权限、并发、取消、隔离和持久化断言。

保留 MCP 连接、发现、调用与刷新；保留现有六个 Backplane V2 协作工具。MCP 当前仍依赖 `Sigma.Coding.Tool`、Dispatcher、结果/元数据及其监督进程，这些共享宿主适配暂时保留。本阶段不另写一套 MCP 执行器，也不把这些共享模块误算成新的 Codex 接入。

保留 hooks、权限配置与审批、路径授权、会话 JSONL、历史工具消息显示、手动技能调用、技能授权与资源、UI 终端和 native terminal helper。Agent 的 `tool_state` 还保存技能授权，不能随 todo store 删除。历史文件和用户配置不迁移、不重写，历史调用不重新执行。

## 模型与用户入口

Web、协议与子代理默认配置均不再引用已删除模块。未配置 MCP 时，Provider 仅收到实际准入的原生协作工具；关闭协作或无持久化 writer 时允许空目录。配置 MCP 时继续发布其已发现的外部工具。

技能上下文不再要求调用已退役的 `read` 或 `activate_skill`。显式技能调用通过现有 `SkillInvocationService` 展开及只读资源路径继续工作。旧工具测试专用实现只能放在 `test/`，不得在生产入口重新注册。

## 验收

1. 生产代码、应用依赖和当前文档中不存在旧工具模块的有效引用；历史记录中的工具名保留。
2. Web 与协议默认目录不再包含旧内置工具；普通聊天和空目录运行通过。
3. MCP 工具发现、执行、结果和目录刷新仍通过；协作宿主、子代理取消及隔离断言保留。
4. 显式技能调用、技能资源、hooks、权限、路径限制和历史读取的相关测试通过。
5. 严格编译、修改文件格式检查及受影响范围测试通过。范围外失败报告并停止，不顺手修复。

本阶段不发布、不部署、不重启既有服务，不修改 `deps/`，也不实现下一阶段的 Codex 工具。
