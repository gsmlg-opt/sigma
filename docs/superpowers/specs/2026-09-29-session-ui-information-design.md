# Session UI 信息层级与交互优化

- 日期：2026-09-29
- 状态：2026-09-29 用户已确认；除紧凑自动增高输入框（上游 #81 阻塞）外已实施并验证。
- 基线：`6499654`，截图与当前 SessionLive 源码已核对；未做浏览器运行时复现。
- 关联：`docs/features/session-ui/prd.md`、`contract.md` 与 `terminals/prd.md`。

## 1. 目标与已确认方向

以对话为主、统计分层、详情按需展开。消除同一信息在多个默认可见区域的重复，同时保留请求、整轮和会话累计之间的真实语义差异。

用户已确认：中性导航背景；顶部集中会话控制；中央保留紧凑本轮摘要；右栏整合会话详情；输入框默认紧凑并随内容增长；操作副作用说明移到操作发生处；补齐窄屏导航和键盘可达性。

本文批准后，替代原 Session UI PRD 5.2 中“默认展开 request footer，多请求时再追加 turn summary”的展示规则。请求事实与原统计契约不变；实施时同步该 PRD 的相关展示段落，其他协议与计量要求继续有效。

采用现有 Phoenix LiveView、phoenix_duskmoon 和 DuskMoon 语义 token。此页面的中性侧栏遵循项目现有 Session UI PRD 5.1，优先于通用设计技能中的 secondary 侧栏默认配色。

## 2. 当前证据

- 工作目录出现在左栏头部、左栏底部、会话顶部和右栏；但 `workdir` 是项目根目录，`effective_cwd` 是执行目录，两者不相同时必须保留区别。
- 当前模型出现在顶部选择器、右栏 Model 卡和 Runtime 段。
- Context 出现在顶部进度条、右栏 Context 卡、观测 Context 段及预算卡。
- 单请求时仍同时显示 request footer 和 Turn total，重复展示输入、输出与吞吐率。
- 右侧固定栏缺少独立滚动；窄屏左栏隐藏后没有对应导航抽屉。
- 消息区的副作用警告随每条用户消息重复呈现。
- 请求 completed 和整轮 running 来自不同事实。源码显示消息在 message_end 时写入 LiveView stream，后续 metrics 更新没有对应重新插入；这只是终态滞留的候选原因，必须以回归测试证明。
- terminal_panel 当前位于中央 composer 之后，保留此结构和终端生命周期。

## 3. 信息归属

| 信息 | 主要展示位置 | 细节与例外 |
| --- | --- | --- |
| 项目与工作目录 | 左栏项目区域 | 一个可展开位置显示完整路径并支持复制；执行目录不同才额外标明 |
| 会话标题 | 顶部和左栏导航项 | 这是定位与导航的必要重复；完整 ID 在详情中显示并可复制，短 ID 可作为无标题会话的次级辨识 |
| 当前模型 | 顶部选择器 | 已完成请求的历史模型保留在该请求详情，不能被当前选择覆盖 |

| 本轮状态、输入、输出、墙钟耗时 | 该轮摘要 | 使用整轮事实，不拿最后一次请求冒充整轮 |

| 本会话累计 usage 与时间 | 右栏“会话累计” | 按用途/模型分组、覆盖率、继承用量在详情中保留 |

## 4. 页面结构与交互

### 4.1 左栏

使用 surface 系列 token 和配对文字颜色。项目入口、新建会话、会话列表优先；项目设置、Skills 等既有入口保留。选中项有明确背景与文字状态，不依赖颜色单独表达。

读取既有 session summary 的 title。标题缺失或等于原始 ID 时显示“未命名会话”及短 ID 作为次级辨识信息，不调用模型生成标题、不修改文件身份。顶部采用同一标题解析规则。现有重命名行为不在本次更改范围。

桌面支持收起/展开；菜单按钮在键盘聚焦与触屏下可发现。完整路径只在项目详情内出现一次；项目根与执行目录不同则分别标注。已有可靠最后活动数据可以显示，没有则不猜测；本轮不引入所有会话的运行时轮询。

### 4.2 顶部与运行阶段

顶部只保留左栏开关、可读会话标题、当前阶段、模型选择、终端入口、详情开关。当前阶段直接使用现有 runtime phase 映射，并区分运行、等待审批、压缩、取消中、失败等状态。模型忙状态禁用及其 runtime guard 保持有效。

手动 Compact 移入 Context 卡片，保留现有安全操作和禁用条件。详情关闭时，预算异常或压缩阈值提示提供重新打开卡片的入口；不在顶部复制整套数字。

### 4.3 对话与本轮摘要

保留正文阅读宽度、代码块局部横向滚动和原有消息顺序。每个可识别 turn 默认只显示一条摘要：状态、整轮墙钟耗时、输入和输出；多个请求或有工具时增加请求/工具数量。未知计数不补零，部分 usage 明确标识为已知部分。

“请求明细”默认折叠，按已有 request 身份展示各请求的 token、请求耗时、请求吞吐率、状态、provider/model、首输出、TTFT、缓存及 reasoning 等数据。完成请求和仍在执行的 turn 可以并存，但必须在各自标注的范围中呈现。

有最终 assistant 回答时，摘要位于该轮最后一个回答之后；运行中先使用该轮当前可用的最后一个展示位置。失败、取消或 tool-only turn 没有最终文字回答时，仍在该轮尾部展示摘要，不能因没有回答气泡而消失。旧记录无法关联 turn 时保留明确标注的请求统计，不构造虚假汇总。

metrics 终态和迟到 usage correction 必须更新对应摘要，保持 terminal 状态不倒退。优先定点更新受影响的 stream 条目；不通过全量重建消息列表修复，避免焦点、滚动、选择和折叠状态丢失，也不每次 token delta 扫描 journal。

### 4.4 右栏

桌面宽屏默认展开，可随时收起；默认行为延续现有桌面可见性。使用同一组内容组件提供三组信息：

1. **会话累计**：own input/output、已知总量、usage coverage；开始时间、活跃时间、加权平均请求吞吐率。用途/模型分组与继承用量按需展开。
2. **上下文与压缩**：当前估值、模型窗口、进度与自动压缩阈值、距离阈值余量、成功压缩次数和最后结果；测量来源、最近实测、检查阶段及预算细节可展开。
3. **连接与元数据**：provider/session 身份、MCP、fork 来源和既有分支入口。当前模型和工作目录不再常驻重复卡片。

右栏独立滚动，最后一项在短视口仍可达。保留已有 branch alternatives 操作与统计归属，不能因为分组调整删除历史或继承信息。

MCP 状态只能来自既有可靠连接状态。若现有页面只有配置的 server ID 列表，则展示“已配置 N 个服务器 / 连接状态未提供”及已有设置入口，绝不将配置数量标成已连接；不为本次视觉优化新增连接探测服务。

### 4.5 Context 文案与数值

截图样例应解释为：

- 下一请求估值：约 19.8K tokens（精确值 19,798）。
- 模型窗口：512K tokens。
- 自动压缩阈值：409.6K tokens。
- 距自动压缩阈值：389,802 tokens。
- 上次请求实测输入：20,176 tokens（放在测量详情）。

采用 runtime 已返回的 threshold 和 tokens_remaining，不在前端复刻压缩策略。进度条的分母明确为模型窗口，阈值为独立标记。未知窗口不画 0% 假进度；估值 stale 时标出失效，不能伪装为当前可用预算。达到阈值时使用“等待安全检查点”，不承诺即时压缩。

自动压缩阈值余量与请求硬预算分别标注：389,802 不是还可追加的输入量。硬预算的 overflow 状态与输出预留仅展示 runtime 已提供的数据；未提供时标明未知，不用阈值余量替代，也不自行推导一个“可发送 token 数”。硬预算异常不得藏在默认折叠的测量详情中。

累计 usage 不等于当前 Context；继承 usage 不并入本会话 own usage；token 不推算金额或订阅剩余额度。

### 4.6 输入区和副作用提示

默认约 2–3 行，随内容增长，并保留现有中央容器的高度上限与内部滚动。附件、发送/停止、快捷键提示形成一致的工具栏。快捷键说明必须使用当前实际发送配置，不能只改标签。

使用现有 dm_chat_input 公共属性/样式能力，不通过 shadow DOM 私有结构或替代组件规避缺失能力。核对现有 `duskmoon-elements#77` 的边界；若所需能力在依赖中缺失，按仓库 upstream issue 规则处理，blocker 不做本地替代。

提交失败保留正文与附件；取消请求后等待 runtime 确认，不提前恢复为可重试状态。终端继续直接停靠在 composer 下方，支持现有最大化/恢复行为。

移除每条用户消息下常驻的长警告。Retry/Fork 在现有操作确认处明确说明不会回滚文件、命令、Git 或外部请求，以及工作目录可能共享。Resend 在操作入口旁有可键盘/触屏展开的行为说明，不能只放 hover tooltip；沿用现有显式执行动作，不引入每次发送的额外确认门槛。

### 4.7 响应式与可访问性

- 宽度至少 1280px：左导航、中央工作区和可收起右栏。
- 768–1279px：左导航与中央工作区；右侧详情使用抽屉。
- 小于 768px：中央工作区；左导航和右侧详情各有顶部入口，同一时刻最多打开一个抽屉。
- 窄屏抽屉有可访问名称、dialog/modal 语义、打开时焦点进入、Tab 焦点约束、Escape/关闭按钮/遮罩关闭与关闭后焦点恢复；背景不可交互。
- 桌面栏为非模态导航/互补区域，不套用模态焦点约束；断点切换清理焦点和遮罩状态。
- 所有图标操作具有名称和可见焦点；菜单不得只在 hover 才可发现。
- 正文、次级信息与诊断明细分层；不增加字体下载或第二套 UI 框架。
- 320/390/1024/1440/1920 宽度以及短高度、明暗主题均无整页横向溢出或不可达内容。

## 5. 数据边界与修改范围

沿用现有 runtime snapshot、session_metrics、context policy 和 journal 的事实来源。Web 层负责展示、格式化及局部更新，不重新累计 usage，不修改协议、压缩阈值、会话文件格式或 agent engine 默认值。

允许修改：

- `apps/sigma_web/lib/sigma_web/live/session_live.ex`：页面组合、标题解析、UI 开关及 metrics 后的定点 stream 更新。
- `apps/sigma_web/lib/sigma_web/components/session_observability.ex`：分层统计、Context 与元数据组件。
- `apps/sigma_web/assets/css/app.css`：仅 session 范围的布局、语义颜色、滚动及 composer 约束。
- `apps/sigma_web/assets/js/app.js`：仅必要的会话交互 hook 注册或现有输入配置。
- 可新增 `apps/sigma_web/assets/js/hooks/session_panels.js` 及 `session_panels_test.js`：仅当 DuskMoon/LiveView 已有公共能力不能直接组合出焦点与断点处理时使用，不另造组件体系。
- `apps/sigma_web/test/sigma_web/live/session_live_test.exs`、`apps/sigma_web/test/sigma_web/components/session_observability_test.exs`：针对行为的回归覆盖。
- `apps/sigma_web/test/sigma_web/components/session_terminal_components_test.exs`、`apps/sigma_web/assets/js/chat_submission_test.js`、`apps/sigma_web/assets/js/chat_attachments_test.js`：仅在受影响接口需要调整测试时修改。
- 本设计、对应实施计划及本次验收记录。
- `docs/features/session-ui/prd.md`：仅同步被本设计替代的展示规则及相关展示验收，不改动计量或协议契约。

不修改全局 appbar、其他页面、依赖包源码、后端累计模型、协议或 journal。如果状态回归证明错误超出 Web 层，单独报告根因与所需范围；不将未验证的状态强制改为 completed。

## 6. 实施顺序与并行边界

1. 先写能验证 turn_finished/迟到 usage correction 的聚焦回归，确认状态滞留根因与修复范围。
2. 并行处理观测组件分层，以及 session 样式/输入公共能力核对；各自限定文件所有权。
3. 单一集成者修改 SessionLive：顶部、导航、抽屉、组件组合、操作提示与 stream 更新，避免多个代理同时改同一大文件。
4. 合并后运行 scoped tests，随后进行浏览器验收。Mix/devenv 构建串行执行。

实现不包含自动提交、推送、合并或部署；这些操作需要独立授权。
